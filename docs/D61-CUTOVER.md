## 1. ซ้อมในห้องซ้อม (ไม่กระทบลูกค้าจริงแม้แต่นิดเดียว)

1. เปิด `/train` → กดปุ่มมุมขวาบน **"ชีต: v2"** ให้เป็น **"ชีต: v3"** (ปุ่มถาวร สลับกลับได้ตลอด)
2. กด **🔄 reset** เริ่มบทใหม่
3. เดินอย่างน้อย 5 บท:
   - ทักเปล่า → เลือกโปร → โอน → ส่งสลิป → ให้ที่อยู่ → ปิดจบ
   - COD เต็มวงจร (คอนเฟิร์มยอด → ที่อยู่)
   - "1 ถ้วยเท่าไหร่" (S2Q — ต้องไม่สรุปยอดทันที)
   - ถามค่าส่ง**กลางทาง** S3 (ต้องตอบแล้วพากลับถามโอน/COD ในเทิร์นเดียว)
   - "แพ้กุ้งทานได้ไหม" (ต้องถามกลับ/ให้ข้อเท็จจริง · **ห้ามมีคำรับรอง** · ไม่ปิดบอท · 🔔 เข้ากลุ่มครั้งเดียว)
4. ระหว่างซ้อม แตะบอลลูนดู X-ray ต่อเทิร์นได้ (ดูว่า stage/gate/verbatim ตรงไหม)

> 🔴 **ห้องซ้อม v3 ไม่แตะ prod:** override อยู่ใน ALS ต่อ session · prod ไม่มี context → อ่าน env เสมอ · loader/config ไม่เขียน cache ร่วมในโหมด sandbox

## 4. สลับ production

1. Vercel → Settings → Environment Variables → **`SHEET_SCHEMA` = `v3`** (Production)
2. Redeploy
3. ยิงข้อความทดสอบ 1 ข้อความจาก LINE จริง (บัญชีตัวเอง) → ดูว่าตอบด้วยสมองใหม่

## 5. เฝ้า 24 ชม.แรก (ดูใน Vercel logs — กรองด้วย `scope`)

| scope | ดูอะไร |
|---|---|
| `assurance-guard` | `hit` = AI พยายามรับรอง (ปกติได้) · `cut`/`fallback` บ่อย = prompt ต้องเกลา |
| `health-flag` | ธงติดตรงเคสที่ควรติด |
| `price-guard` / `claims-guard` | **ต้องเงียบ** — มีขึ้น = ตรวจทันที |
| `sheets-v3` | `header-missing` = ชีตถูกแก้ผิด → รีบแก้ |
| `degraded` / `extraction` | ถี่ผิดปกติ = โมเดล/prompt มีปัญหา |
| `closing-split` | splitter ทำงานบ่อย = โมเดลเลิกใส่ `[[เว้น]]` เอง (ปกติควรเงียบ — ตาข่ายสำรอง) |
| dashboard | handoff ค้าง · ออเดอร์ "รอคอนเฟิร์ม" ผิดปกติ |

## 5.1 หลังสลับ 2-3 วัน — ยืนยันต้นทุน LINE ด้วยตัวเลขจริง

🔴 **v3 ปิดโหมดประหยัดโควตาโดยเจตนา** (D-61.C6 · จังหวะบอลลูนคือดีไซน์ CX) → 1 เทิร์นส่ง 3-5 บอลลูนแทน 1-2

- เปิด **LINE OA Manager → สถิติ/จำนวนข้อความที่ส่ง** เทียบยอดก่อน/หลัง cutover
- **สิ่งที่คาด:** ยอดที่ "นับโควตา" **ไม่เพิ่ม** — เทิร์นตอบปกติใช้ **Reply API** (`deliverReply` ยิง reply ก่อนเสมอ · push เฉพาะตอน reply token หมดอายุ) และ `replyMessage` ส่ง 5 messages ต่อ **1 API call** · ตามนโยบาย LINE reply ไม่นับโควตา (push/multicast/broadcast นับ)
- ⚠️ **ข้อนี้ยังไม่เคย verify กับบัญชีจริงของร้าน** — ถ้ายอดพุ่งขึ้นตามจำนวนบอลลูน = สมมติฐานผิด ให้เปิดงาน **D-63: โหมดประหยัดแบบ scope เฉพาะ push** (ยุบเฉพาะตอน fallback ไป push · เทิร์น reply ยังแยกบอลลูนเต็ม) — ไม่ใช่กลับไปยุบทั้งเทิร์น

## 6. Rollback (1 สวิตช์ · ~1 นาที)

**เงื่อนไขที่ต้อง rollback ทันที:**
- คำรับรองสุขภาพหลุดถึงลูกค้า (แม้ครั้งเดียว)
- ราคา/ยอดผิดหลุดถึงลูกค้า
- บอทเงียบ/ตอบไม่ตรงเรื่องเป็นระบบ
- ออเดอร์เขียนชีตผิด/ไม่เขียนทั้งที่ครบ

**วิธี:** Vercel → `SHEET_SCHEMA` = `v2` (หรือลบตัวแปร) → Redeploy
- ไฟล์ชีต v2 **ไม่เคยถูกแตะตลอด D-61** → กลับไปพฤติกรรมเดิม 100% ทันที
- ข้อมูลลูกค้า/ออเดอร์ (Neon + ชีต Orders) ใช้ร่วมกันทั้งสองโหมด → ไม่มีอะไรต้องกู้
- ห้องซ้อมยังสลับดู v3 ได้ต่อ (ปุ่มถาวร) เพื่อหาสาเหตุ

## ภาคผนวก · จุดที่ v3 ต่างจาก v2 โดยตั้งใจ (กันเข้าใจผิดว่าเป็นบั๊ก)

- **บอทเรียบเรียงคำเอง** — คำตอบจะไม่เหมือนชีตเป๊ะอีกต่อไป (ชีตให้ "สาระ" ไม่ใช่สคริปต์)
- **ลำดับใหม่: ชำระเงินมาก่อนที่อยู่**
- **เรื่องสุขภาพไม่ปิดบอทแล้ว** — บอทให้ข้อเท็จจริง + 🔔 แจ้งกลุ่ม (เดิม: ปิดเงียบ)
- **`คำ_handoff` เหลือเฉพาะเจตนาเรียกคน** (สุขภาพย้ายไป `คำ_ธงสุขภาพ`)
- **Follow ไม่มีใน v3** (dormant · cron skip พร้อม log)
- **แท็บ Objections ยุบรวมเข้า "ความรู้"**
