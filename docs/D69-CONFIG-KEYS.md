## ข้อควรระวังต่อคีย์

**`ระดับการคิด`** — 🔴 Gemini คนละตระกูลรับคนละแบบ:
- `gemini-3.x` รับ **คำ** (`minimal`/`low`/`medium`/`high`) เท่านั้น — ใส่ตัวเลขไม่ได้
- `gemini-2.x` รับ **ตัวเลข** เท่านั้น (`0` = ปิดการคิด · `-1` = อัตโนมัติ)
- ใส่ผิดแบบ → **บอทไม่พัง** · ระบบใช้ค่าเริ่มต้นแทน + เขียน log เตือน (`thinking-invalid`)
- คิดมากขึ้น = ตอบดีขึ้นแต่ **ช้าลงและแพงขึ้น** (thinking นับเป็น output token)

**`timeout_วินาที`** — ระบบมีเพดานของตัวเอง:
- งบรวมต่อเทิร์น = `หน่วงรวบข้อความ + คอลหลัก + คอลเขียนใหม่(ครึ่งหนึ่ง)` ต้องไม่เกิน **54 วินาที**
- ใส่เกินงบ → ระบบ **บีบลงให้เองอัตโนมัติ** + เขียน log เตือน (`timeout-clamped`) ไม่ปล่อยให้ Vercel ตัดกลางคัน
- ตั้งต่ำเกิน (เช่น 5) = บทยาวจะ degraded บ่อยขึ้น

**`ข้อความ_ระบบช้า`** — ใช้ตอนบอทตอบไม่ทัน:
- 🔴 **อย่าเขียนว่า "ไม่ได้รับข้อความ"** (ไม่จริง — ระบบได้รับแล้วแต่ตอบไม่ทัน)
- 🔴 **อย่าสั่งให้ลูกค้าพิมพ์ซ้ำ** — บทจะยาวขึ้น → ยิ่งช้าลง → เป็นวงจรที่ทำให้อาการแย่ลงเอง
- 🔴 **อย่าสัญญาว่าบอทจะกลับมาตอบเอง** — ระบบไม่มีการลองใหม่อัตโนมัติ
- ทุกครั้งที่ข้อความนี้ถูกส่ง ระบบ**แจ้งกลุ่มแอดมินให้อัตโนมัติ** (ไม่ปิดบอท) → ประโยค "แจ้งทีมแอดมินให้แล้ว" เป็นเรื่องจริง

## ดูผลที่ไหน

- **ตาราง `ai_usage` ใน Neon** — 1 แถวต่อ 1 การเรียก: โมเดล · tokens · `cached_tokens` · เวลา(ms) · `call_kind`
  - `call_kind = 'regen'` คือเทิร์นที่ยิงซ้ำเพราะ assurance guard = **จ่ายสองเท่าในเทิร์นเดียว** ถ้าเห็นถี่ ให้บอก
  - `cached_tokens > 0` = Google ลดราคาให้อัตโนมัติอยู่แล้ว (implicit caching)
- **log `scope: "ai-usage"`** ใน Vercel — ตัวเลขเดียวกัน + ประเมินค่าใช้จ่าย
- 🔴 **ตัวเลขค่าใช้จ่ายในระบบเป็นแค่ค่าประมาณ** — ตัวเลขจริงให้ดู cost log รายวันของ Google ต่อ API key
